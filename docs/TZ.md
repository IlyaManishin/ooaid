# ТЗ: TrackFit (Android)

Версия ТЗ: 1.0 (24.11.2026). Основание: `docs/trackfit.md` (правила, ред. 17.11.2026), `docs/UI.drawio` (3 листа).
Архитектура — в `docs/ARCHITECTURE.md`. Решения по неясностям — в `docs/DECISIONS.md` (ссылки `D-xx`).

---

## 1. Цель

Автономное Android-приложение для планирования и отслеживания тренировок с виртуальным тренером. **Только клиент**: бэкенда, аккаунтов, сети нет. Все данные — локально на устройстве.

## 2. Границы

**В объёме:** конструктор программ; запуск программы с выбранного дня; календарная привязка циклов; тренировочная сессия с таймером и статусами; итоги дня/цикла; push-уведомления; виртуальный тренер (детерминированный); профиль, личные рекорды, настройки.

**Вне объёма (не делать):** сеть/синхронизация/бэкап, регистрация, генеративный ИИ, аналитика, реклама, локализации кроме русской, планшетная вёрстка, виджеты рабочего стола, wear, экспорт/импорт, экран «Прогресс» с наполнением (макета нет — только заглушка, D-12), удаление программ (нет в макете), перенос/перестановка тренировок между днями (запрещено правилами).

## 3. Платформа и стек

- Kotlin, Android SDK, `minSdk 26`, single-Activity, портретная ориентация.
- UI: Jetpack Compose + Material 3, Navigation Compose.
- Асинхронность: Kotlin Coroutines + Flow.
- DI: Hilt (KSP). Допускается ручной DI только при блокирующей несовместимости (записать в `DECISIONS.md`).
- Хранение: Room (структурные данные) + DataStore Preferences (простые настройки).
- Сериализация снапшотов: kotlinx.serialization (DTO в `:infra`, не в домене).
- Время: `java.time` (доступно с API 26 без desugaring).
- Тесты: JUnit, kotlin-test, Turbine (Flow), Robolectric (Room/репозитории на JVM). Mockito/MockK не нужны — используем фейки портов.
- Сборка: Gradle Kotlin DSL, version catalog, Gradle wrapper в репозитории.
- Окружение: `docs/SETUP.md`.

## 4. Домен: термины (RU ↔ EN идентификаторы)

| Цикл | `Cycle` (набор `DaySlot`) | Упорядоченные дни двух типов. |
| Рабочий день | `CycleDay.Work` | name, длительность (мин, обяз.), автостарт (опц.), ≥1 упражнений. |

| Запуск программы | `ProgramRun` | Активная программа + прогресс. Не более одного. |

## 5. Функциональные требования

Нумерация `F-xx` — для ссылок в коммитах/тестах. Все правила — из `trackfit.md`; здесь они сведены и дополнены решениями.

### 5.1 Программы и конструктор (макет: PROGRAMS, PROGRAM_EDITOR, DAY_EDITOR, модалки упражнений)

- **F-01** Экран «Мои программы» показывает список программ (название, ✏️ редактировать, `>` выбрать). Кнопка «Добавить новую программу» открывает конструктор с пустым черновиком.
- **F-02** Редактирование разрешено только неактивной программе. Для активной программы ✏️ недоступна (скрыта или неактивна — на усмотрение агента, зафиксировать в `UI_MAP.md`).
- **F-03** Конструктор: поле «Название программы», вертикальный список карточек дней (`#N`, название, тип-чип, строка-описание, ▲▼ перестановка, 🗑 удаление), кнопки «Добавить тренировку» / «Добавить день отдыха», «Сохранить».
- **F-04** «Добавить тренировку»: создаёт `Work` с именем по умолчанию (D-02) и сразу открывает экран настройки дня. «Добавить день отдыха»: добавляет `Rest` без настроек.
- **F-05** Экран настройки рабочего дня: название, длительность (мин, обязательно, ≥1), время автостарта (опционально), список упражнений, «Добавить упражнение», «Готово».
- **F-06** Добавление упражнения: модалка выбора типа → модалка параметров типа. Обязательные/опциональные поля и что показывать в списке — по таблице в макете (лист 2, блок «Типы упражнений и их параметры»; продублировано в `UI_MAP.md` §5). Все обязательные поля должны быть заполнены для сохранения. Тип существующего упражнения не меняется (D-24). Порядок упражнений = порядок добавления (без перестановки, C).
- **F-07** Валидация программы при «Сохранить»: ≥1 день; ≥1 рабочий день; в каждом рабочем дне ≥1 упражнение и длительность ≥1; название программы непустое. Ошибки показываются на экране, сохранение блокируется. Правила — только в `:domain` (`ProgramValidator`).
- **F-08** Конструктор работает с черновиком; выход «←» без «Сохранить» отбрасывает изменения (без диалога — в макете его нет).
- **F-09** Заметки упражнений не отображаются в списке упражнений дня (D-04), но показываются на экране активной тренировки.

### 5.2 Запуск программы, цикл, календарь (макет: HOME, PROGRAMS, START_DAY_PICKER)

- **F-10** Не более одной активной программы. Запуск возможен только при отсутствии активной (D-03).
- **F-11** Выбор программы (`>` на PROGRAMS) → модалка «С какого дня начать сегодня?» со списком **всех** дней цикла (по умолчанию выбран первый; в макете выбран «День 2» как пример) → «Начать программу» / «Отмена».
- **F-12** Старт: выбранный день привязывается к **сегодняшней** дате, далее дни идут по кругу, 1 день цикла = 1 календарные сутки. Цикл длится ровно N суток (N = число дней). После «Начать программу» — переход на HOME.
- **F-13** Нельзя перескакивать, переносить, переключаться между днями. Запустить тренировку можно только в день её слота (= сегодня).
- **F-14** HOME (программа активна): заголовок = название программы, кнопка «Остановить», полоса «Календарь цикла» (дата, название дня/«День отдыха», маркер: сегодня / заблокирован будущий / статус прошедшего), карточка «СЕГОДНЯ» (см. F-30..F-33), кнопка «Мои программы».
- **F-15** HOME (программы нет): текст «Активная программа отсутствует…» + «Мои программы».
- **F-16** «Остановить» (на HOME): немедленно очищает прогресс текущего цикла и деактивирует программу, открывается HOME без программы (подтверждения в макете нет, D-11). Лог тренировок и рекорды не затрагиваются (D-12).
- **F-17** Окончание цикла: когда закрыт последний слот цикла, цикл переходит в фазу ожидания решения (D-08/D-09). Решение принимается в модалке итогов цикла:
  - «Да, сменить программу» → прогресс очищается, программа деактивируется, открывается PROGRAMS;
  - «Нет, начать новый цикл» → статусы сбрасываются, новый цикл этой же программы стартует **со следующих суток** с того же стартового дня, номер цикла +1.
- **F-18** Итог цикла (считается строго **до** сброса статусов): *полный успех* — все рабочие дни «Завершено»; *полный провал* — все рабочие дни «Пропущено»; иначе *частичный успех*.

### 5.3 Тренировочная сессия (макет: HOME, WORKOUT)

- **F-30** Параметры рабочего дня: длительность (жёсткий дедлайн), автостарт (опционально).
- **F-31** Ручной старт: кнопка «Начать тренировку» на карточке сегодняшней тренировки (статус «Не начато») → статус «Выполняется», открывается WORKOUT. Разрешён и при заданном автостарте (D-05).
- **F-32** Автостарт: если задано время, в этот момент своего дня сессия стартует сама (даже если приложение закрыто — через логику reconcile, см. архитектуру). Для первого слота нового запуска программы автостарт действует, только если время ещё не прошло (D-06).
- **F-33** HOME при статусе «Выполняется»: карточка показывает «Выполнено упражнений: k из n», «Оставшееся время», кнопка «Перейти к тренировке». Выход на HOME не прерывает сессию.
- **F-34** WORKOUT: заголовок (название дня, «Идёт тренировка (k из n выполнено)»), таймер «Осталось», карточки упражнений с чекбоксом, «Завершить тренировку». Отмеченное упражнение серое и блокируется (снять нельзя). Состав параметров в карточке — по типу упражнения; заметка показывается.
- **F-35** Сессия закрывается: вручную («Завершить тренировку»); по дедлайну (`start + длительность`); в 00:00 следующих суток (дедлайн не может выходить за полночь своего дня, D-07), в том числе если тренировка так и не стартовала.
- **F-36** Статус по закрытию: n из n → «Завершено»; 1…n−1 → «Не завершено»; 0 или не запущена до полуночи → «Пропущено».
- **F-37** Каждое закрытие рабочего дня: (а) пишет `WorkoutLogEntry`; (б) формирует отчёт (F-40). Закрытие дня отдыха отчётов не даёт.

### 5.4 Итоги (модальные окна поверх HOME)

- **F-40** Закрытие рабочего дня создаёт `DayReport`. Если это же закрытие завершает цикл — создаётся **только** `CycleReport` (итог цикла приоритетнее, `DayReport` не создаётся).
- **F-41** Отчёты хранятся до показа. При ручном завершении при открытом приложении модалка показывается сразу поверх HOME. При автозакрытии в фоне (дедлайн, 00:00) показ — при следующем запуске, после загрузки HOME. После закрытия модалки отчёт помечается просмотренным и не показывается повторно. Несколько накопившихся отчётов — по очереди от старых к новым (D-13).
- **F-42** Содержимое `DayReport`: название дня, статус, k из n. Содержимое `CycleReport`: номер цикла, итог (F-18) + вопрос о смене программы (F-17). Модалка итогов цикла не закрывается без выбора (D-09).
- **F-43** В макете экраны 3Г/3Д помечены «ПЕРЕДЕЛАТЬ ПОД МОДАЛЬНЫЕ ОКНА» — реализовать сразу как модальные окна, содержимое взять из этих экранов.

### 5.5 Push-уведомления (платформа)

- **F-50** Дневное напоминание в 12:00: если сегодня рабочий день и статус «Не начато» **на момент срабатывания** — push. Текст — плейсхолдер (D-18).
- **F-51** «Опоздание на автостарт»: в момент автостарта, если приложение не на экране (в фоне/закрыто) — push «Ты опаздываешь? Я подожду!» (исправлена опечатка из `trackfit.md`).
- **F-52** Автозакрытие в 00:00 — **без** push (тихий режим).
- **F-53** Запрос разрешения `POST_NOTIFICATIONS` (API 33+) — в момент, когда оно впервые нужно (первый запуск программы), не на старте приложения. Отказ не ломает приложение.
- **F-54** Переключатель «Push-уведомления» на экране настроек (один общий, D-18) отключает все push.
- **F-55** Расписание уведомлений пересчитывается после каждого изменения состояния, при запуске приложения, при перезагрузке устройства и смене времени/часового пояса.

### 5.6 Виртуальный тренер (макет: COACH_LIST, COACH_CARD + виджет)

Тренер — **детерминированный** персонаж: фиксированный характер, внешность, предзаданная база реплик. Не генеративный ИИ.

- **F-60** Вкладка «Тренер»: список тренеров (аватар, имя, [характер], демо-фраза, ✅ у выбранного). Тап по карточке → карточка тренера (фото, характер, о себе) с кнопкой «Выбрать тренера». Тренеры — данные из assets (3 штуки в макете: Raven, Chloe, Amelie; контент — плейсхолдеры, D-17).
- **F-61** Реплики:
  - **Автостарт при входе:** если сессия уже стартовала автоматически, при входе в приложение — спец-приветствие («Привет! Тренировка уже началась по расписанию. Поторапливайся!» — текст-плейсхолдер банка).
  - **День отдыха:** при входе в приложение в день отдыха — напоминание о важности восстановления.
  - **Результат:** при показе отчёта — реплика по статусу дня / итогу цикла (по приоритету, F-40).
  - **Контекст суток:** если пользователь в эти же календарные сутки уже полностью завершил тренировку (например, до перезапуска программы), повторный успех → усиленная похвала; частичный результат → мягче.
  - **Случайные мотивационные фразы:** ≤1 за тренировку; наименьший приоритет (отменяются любым системным событием); только после ≥10 минут тишины с момента последней реплики; при пересечении сдвигаются на +10 минут; при закрытии тренировки аннулируются (D-16).
- **F-62** Реплика показывается в виджете тренера (аватар + облачко). Время жизни — D-15. Где размещён виджет — D-26.
- **F-63** Архитектура тренера обязана позволять добавлять новые триггеры/правила/персонажей без изменений в UI и в движке (`ARCHITECTURE.md` §10, §13).

### 5.7 Профиль, рекорды, настройки (макет: PROFILE, SETTINGS, PROFILE_EDITOR, RECORDS, RECORD_VIEW, RECORD_EDITOR)

- **F-70** Профиль: аватар (фото), имя, пол, возраст (вычисляется из даты рождения), выбранный тренер, плитки «Мои рекорды» и «Настройки», «Редактировать профиль».
- **F-71** Редактор профиля: имя, пол, дата рождения, аватар; «Сохранить». Все поля опциональны (D-19). Фото — из галереи через системный Photo Picker (без запроса разрешений), копия в приватное хранилище приложения.
- **F-72** Личные рекорды: список (упражнение, «Параметр: значение • …», дата), просмотр, добавление/редактирование (название упражнения + набор параметров «параметр/величина», «＋ Добавить параметр», ⌫ удалить параметр), удаление. Дата рекорда — дата добавления (D-20).
- **F-73** Настройки: строки «Тренер» (ведёт к выбору тренера) и «Push-уведомления» (переключатель). Больше ничего (D-18).
- **F-74** Вкладка «Прогресс»: заглушка (пустой экран с заголовком из `strings.xml`). Лог тренировок копится в БД для будущего UI (D-12).

## 6. Нефункциональные требования

- **N-01 Корректность времени:** приложение, не запускавшееся несколько суток, при следующем запуске приходит ровно в то состояние, как если бы оно работало всё время (автостарты, дедлайны, полуночи, итоги). Это ключевое требование к архитектуре.
- **N-02 Часовой пояс/часы:** «сутки» = календарные сутки в текущем часовом поясе устройства. Перевод часов назад не откатывает закрытое (reconcile монотонен, D-25).
- **N-03 Надёжность данных:** состояние сохраняется транзакционно после каждой команды; убийство процесса в любой момент не портит данные. Миграции Room с экспортом схем; `fallbackToDestructiveMigration` запрещён.
- **N-04 Независимость UI:** замена макетов затрагивает только `:app`.
- **N-05 Производительность:** холодный старт без заметных задержек; никакой тяжёлой работы на main; таймер на экране — обновление раз в секунду только пока экран виден.
- **N-06 Доступность (минимум):** `contentDescription` у иконок-кнопок, размеры касания ≥48dp.
- **N-07 Тестируемость:** `:domain` покрыт юнит-тестами без Android; сценарии времени тестируются через `FakeTimeSource`.
- **N-08 Локализация:** только русский, но строки в ресурсах.

## 7. Данные по умолчанию

- Релизная сборка стартует **пустой** (нет программ). Debug-сборка содержит `DebugSeeder` с тремя примерными программами из макета («Сила и масса», «Ноги и ягодицы», «Фитнес и тонус»), включается флагом (D-21).
- Тренеры (Raven, Chloe, Amelie) — всегда присутствуют (assets). Тренер по умолчанию — первый в реестре (D-17).
