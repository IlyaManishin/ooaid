## 1. ГЛОССАРИЙ: ПОНЯТИЯ И ОПРЕДЕЛЕНИЯ

Для исключения двоякого толкования правил во всей документации и бизнес-логике системы зафиксированы следующие базовые определения:

### Сущности архитектуры
* **TrackFit** — мобильное приложение для планирования, фиксации и отслеживания прогресса тренировок.
* **Программа** — верхнеуровневый шаблон/план тренировок, определяющий упорядоченный перечень тренировочных дней. Программа является неизменяемой во время своей активности.
* **Цикл** — однократное сквозное прохождение активной программы от первой до последней тренировки. Программа может содержать множество последовательных циклов.
* **Тренировочный день (Тренировка)** — структурная единица программы, состоящая из обязательного набора упражнений ($n \ge 1$).
* **Упражнение** — атомарный элемент тренировочного дня. Поддерживаемые типы: *сила*, *гибкость*, *баланс*, *кардио*.
* **Виртуальный тренер** — системный персонаж с фиксированным характером, внешностью и предзаданной библиотекой реплик (детерминированная ролевая модель, **не** генеративный ИИ). Подбирает реплики на основе событийного контекста.

### Статусы тренировочного дня
В рамках одного цикла каждая тренировка может находиться строго в одном из 6 состояний:
1. **«Не начато»** (ранее *«Не тронуто»*) — тренировка ещё ни разу не запускалась в рамках текущего цикла. Является **блокирующим** статусом для автоматического завершения цикла.
2. **«Выполняется»** — тренировочная сессия активна в данный момент времени. В системе может быть не более одной активной тренировки одновременно. Является **блокирующим** статусом для завершения цикла.
3. **«Отложено»** — тренировка была начата, но пользователь переключился с неё на другую активность, не отметив ни одного упражнения ($0$ отметок). Является **блокирующим** статусом для автоматического завершения цикла.
4. **«Не завершено»** — тренировка была прервана или завершена, при этом отмечено от $1$ до $n - 1$ упражнений. Данный статус сам по себе **не блокирует** завершение цикла.
5. **«Завершено»** — тренировка успешно выполнена, отмечены абсолютно все упражнения ($n$ из $n$). Не блокирует завершение цикла.
6. **«Пропущено»** — тренировка закрыта с $0$ отмеченных упражнений без перехода на другую сессию (либо принудительно по дедлайну). Не блокирует завершение цикла.

### Навигация и специальные состояния
* **Прямое переключение** — действие, при котором пользователь переходит к другой тренировке непосредственно из активного экрана текущей сессии (без предварительного отдельного закрытия).
* **Долг** (ранее *«Должок»*) — тренировочный день текущего цикла, сессия по которому была начата, но не доведена до полного выполнения (тренировка со статусом «Отложено» или «Не завершено»).
* **Флаг Hot (Буфер возврата)** — скрытый системный маркер с часовым таймером, устанавливаемый на тренировку при прямом переключении с неё. Предотвращает преждевременное автоматическое закрытие цикла, если пользователь временно ушёл с частично выполненной тренировки.
* **Флаг «Трудолюбие»** — контекстный дневной флаг, который активируется, если пользователь в течение текущих календарных суток полностью завершил хотя бы одну тренировку (статус «Завершено»).
* **Дедлайн тренировки** — фиксированное предельное время на выполнение тренировки. По истечении таймера сессия закрывается автоматически.
* **Дни отдыха** — относительное количество суток между фактическим завершением текущей тренировки и датой следующего рекомендуемого старта.

### Итоги цикла
* **Полный успех** — абсолютно все тренировки цикла имеют статус «Завершено».
* **Полный провал** — все тренировки цикла получили статус «Пропущено».
* **Частичный успех** — любая иная комбинация итоговых статусов.

## 2. НАЗНАЧЕНИЕ И БАЗОВЫЕ ОГРАНИЧЕНИЯ

### Профиль пользователя
* Атрибуты: имя, пол, возраст, выбранный персонаж тренера, аватар.
* Функционал: персональные рекорды, история выполнения, динамика прогресса. (Детальная модель измеряемых метрик упражнений выносится в отдельную спецификацию).

### Системные ограничения (Инварианты)
* У пользователя может быть **не более одной** активной программы единовременно.
* Запрещено создание программы без тренировочных дней ($n_{\text{дней}} \ge 1$).
* Запрещено создание тренировки без упражнений ($n_{\text{упражнений}} \ge 1$).
* В рамках активной программы может выполняться **не более одной** тренировки одновременно.
* В активной программе любое редактирование структуры запрещено. Изменение состава упражнений и тренировок доступно только после деактивации программы.

## 3. МОДЕЛЬ «ПРОГРАММА — ЦИКЛ»

Программа и цикл строго разграничены на уровне логики:

```
[ Программа: шаблон тренировок ]
       │
       ├──> [ Цикл 1 (прохождение) ] ──> Завершён (Итог зафиксирован)
       ├──> [ Пауза / Ожидание ]
       └──> [ Цикл 2 (прохождение) ] ──> ...
```

### Программа
* Хранит эталонный список тренировочных дней и порядок их следования.
* Активируется пользователем по кнопке «Начать программу».
* Во время активности заблокирована для редактирования.
* Остаётся активной после завершения любого количества циклов до явного нажатия пользователем кнопки «Завершить программу».
* При принудительном завершении программы посреди незавершённого цикла текущий цикл сначала закрывается по общим правилам, после чего программа переходит в неактивный статус. Повторная обработка закрытия для уже завершённого цикла запрещена.

### Цикл
* Представляет собой единичную итерацию прохождения программы.
* Хранит текущие статусы тренировок и прогресс выполнения упражнений.
* Следующий цикл **никогда не стартует автоматически** — только по явному действию пользователя («Начать цикл»).
* **Фиксация итога:** результат цикла рассчитывается строго **до** сброса состояний.
* **Процедура закрытия цикла (единая атомарная транзакция):**
  1. Вычислить итог цикла (Полный успех / Частичный успех / Полный провал).
  2. Зафиксировать результат для вызова соответствующей реакции тренера.
  3. Сбросить состояния всех тренировок в статус **«Не начато»**.
  4. Сбросить указатель следующей тренировки на первую по порядку.
  5. Снять флаг Hot и аннулировать его таймер.
* При ручном нажатии кнопки «Завершить цикл» состояние флага Hot игнорируется.

## 4. СТАТУСНАЯ МОДЕЛЬ ТРЕНИРОВОК

Результат закрытия тренировочной сессии зависит от числа выполненных упражнений и контекста выхода:

| Отмечено упражнений | Действие пользователя / Событие | Итоговый статус | Влияние на цикл |
| :--- | :--- | :--- | :--- |
| **$0$** | Прямое переключение на другую тренировку | **«Отложено»** | Блокирует автозавершение |
| **$0$** | Завершение сессии без перехода / Истёк таймер | **«Пропущено»** | Не блокирует |
| **От $1$ до $n - 1$** | Прямое переключение / Завершение / Истёк таймер | **«Не завершено»** | Не блокирует (если нет Hot) |
| **Все ($n$ из $n$)** | Завершение сессии / Истёк таймер | **«Завершено»** | Не блокирует |

> **Правило модального окна:** при нажатии «Завершить тренировку» с $0$ отметок система предлагает выбор:  
> 1. *«Перейти на другую доступную тренировку»* $\to$ текущая получает статус **«Отложено»**.  
> 2. *«Завершить без перехода»* $\to$ текущая получает статус **«Пропущено»**.

## 5. ПЕРЕКЛЮЧЕНИЕ, ВОЗОБНОВЛЕНИЕ И СОХРАНЕНИЕ ПРОГРЕССА

### Прямое переключение
Действие, при котором пользователь из экрана выполняемой тренировки сразу инициирует запуск другой доступной тренировки. Отличается от сценария «Завершить $\to$ выйти в меню $\to$ запустить другую».

* Переключиться разрешено на тренировки со статусами: **«Не начато»**, **«Отложено»**, **«Не завершено»**.
* При прямом переходе исходная тренировка переходит:
  * в **«Отложено»**, если отметок $0$;
  * в **«Не завершено»**, если отмечена хотя бы $1$ отметка.

### Сохранение прогресса
* Все отметки упражнений сохраняются в рамках текущего цикла.
* При возврате к тренировке со статусом «Не завершено» пользователь продолжает с прерванного места; повторно отмечать сделанные упражнения не требуется.

### Работа таймера при возобновлении
* В отличие от отметок прогресса, **таймер продолжительности тренировки не сохраняет остаток**.
* При каждом повторном открытии/возобновлении тренировки таймер запускается с полной базовой длительности, указанной в настройках (например, полные $3$ часа вне зависимости от того, сколько времени прошло ранее).

## 6. ТАЙМЕР ТРЕНИРОВКИ И ДЕДЛАЙНЫ

* **Продолжительность сессии** — обязательный параметр тренировки, выступающий жёстким дедлайном. Пользователю рекомендуется указывать запас в $30\text{–}60$ минут сверх расчётного времени.
* **Принудительное закрытие:** при истечении времени таймера сессия закрывается автоматически по фактически выставленным отметкам ($0 \to$ «Пропущено», $1\dots n-1 \to$ «Не завершено», все $\to$ «Завершено»).
* **Приоритет финала:** если автоматическое завершение тренировки одновременно приводит к закрытию цикла, система показывает **только итог цикла** (индивидуальная реплика завершения тренировки подавляется).

## 7. УСЛОВИЯ ЗАВЕРШЕНИЯ ЦИКЛА И ВЫБОР СЛЕДУЮЩЕЙ ТРЕНИРОВКИ

### Правила автозавершения цикла
Цикл завершается автоматически тогда и только тогда, когда одновременно выполнены два условия:
1. В цикле **отсутствуют** тренировки с блокирующими статусами: **«Выполняется»**, **«Не начато»**, **«Отложено»**.
2. Отсутствует активный системный флаг **Hot** (или его таймер истёк).

> Тренировки со статусами «Завершено», «Не завершено» и «Пропущено» закрытие цикла не блокируют.

### Алгоритм автоподбора следующей тренировки
Логика выбора следующей рекомендованной тренировки отделена от проверки финиша цикла:
1. Начиная с позиции, следующей за текущей тренировкой, выполняется циклический перебор списка.
2. Выбирается первая встретившаяся тренировка со статусом **«Не начато»** или **«Отложено»**.
3. Тренировки со статусом **«Не завершено» в автоматической циклической очереди не участвуют** (к ним пользователь возвращается явно).
4. Если подходящей тренировки не найдено, запускается проверка условий завершения цикла (с учётом Hot).

## 8. СИСТЕМНЫЙ ФЛАГ HOT (БУФЕР ВОЗВРАТА)

### Назначение
Предотвратить внезапное закрытие цикла, когда пользователь временно переключился с частично выполненной тренировки (получившей статус «Не завершено», который сам по себе не блокирует цикл), рассчитывая вернуться к ней позже.

### Правила флага Hot
* Флаг полностью скрыт от интерфейса пользователя.
* Может быть установлен **только на одной** тренировке в системе единовременно.
* Снимается при запуске/возобновлении именно той тренировки, на которой он установлен.
* Очищается при любом завершении цикла вместе со своим таймером.

### Условия установки Hot при прямом переключении
Флаг Hot устанавливается на исходную тренировку **только при одновременном соблюдении условий**:
1. На исходной тренировке есть хотя бы одна отметка (она переходит в «Не завершено» и теряет естественную блокировку цикла).
2. Оценка системы «на шаг вперёд»: если мысленно исключить целевую тренировку (которая перешла в «Выполняется»), в цикле **не остаётся других тренировок** со статусами «Не начато» или «Отложено». То есть без флага Hot завершение целевой тренировки привело бы к моментальному закрытию цикла.

*Если на исходной тренировке $0$ отметок, она становится «Отложено» — данный статус сам по себе блокирует цикл, поэтому Hot не выставляется.*  
*Если в цикле есть ещё хотя бы одна тренировка «Не начато» или «Отложено», Hot не выставляется.*

### Перенос флага Hot
Если пользователь совершает прямое переключение на тренировку, на которой уже стоял Hot:
* С целевой тренировки Hot снимается.
* Если исходная тренировка удовлетворяет правилам установки Hot, флаг переносится на неё.
* Если не удовлетворяет — флаг аннулируется.

### Работа таймера Hot
* Исходное значение таймера — $1\text{ час}$ ($60\text{ минут}$).
* **Заморозка:** пока в приложении выполняется любая тренировка («Выполняется»), таймер Hot заморожен.
* **Отсчёт:** отсчёт часа начинается только тогда, когда активных тренировок нет.
* **Сброс:** если при активном Hot запускается другая тренировка, таймер сбрасывается на полные $60$ минут и снова замораживается на время её проведения.
* **Истечение:** по истечении $1$ часа автоматическое закрытие цикла срабатывает только в том случае, если отсутствуют иные блокирующие факторы. Сам по себе таймер Hot не завершает цикл при наличии тренировок «Не начато» или «Отложено».

## 9. РАСПИСАНИЕ И ДНИ ОТДЫХА

* В настройках каждой тренировки задаётся обязательное относительное количество **дней отдыха** до следующей тренировки по умолчанию.
* Расписание является относительным и не привязывается к дням недели.
* Расписание регулирует исключительно **автоматический запуск**; вручную пользователь может стартовать любую тренировку в любой момент.

### Правила расчёта даты следующей тренировки
* Дата рассчитывается на основе **последней фактически завершённой тренировки** за текущие календарные сутки, получившей статус «Завершено», «Не завершено» или «Пропущено».
* Конкретный статус на дату не влияет — берутся настройки дней отдыха именно этой завершённой тренировки.
* Статус «Отложено» пересчёт не инициирует (это прерванная сессия).
* Во время активной тренировки переменная даты следующего автоматического запуска принимает значение `NULL`.
* При досрочном ручном выполнении тренировки дата пересчитывается заново от нового фактического дня завершения.

## 10. АВТОСТАРТ, ПРИВЕТСТВИЯ И УВЕДОМЛЕНИЯ

### Время автоматического запуска
* Опциональная настройка конкретного времени суток.
* Если время задано, а пользователь не открыл приложение вовремя, отправляется push от тренера (*«Ты опаздываешь? Я подожду!»*).
* При открытии приложения после автостарта тренер показывает специальное приветствие (*«Привет! Тренировка уже началась по расписанию. Поторапливайся!»*), заменяющее обычные реплики.
* Если время не задано, сессия завершается в $00:00$ следующих календарных суток. Итоговый ночной push в этом случае **не отправляется**, чтобы не беспокоить пользователя.

### Регламент системных уведомлений
1. **Дневное напоминание о тренировке:** ежедневно в 12:00 система проверяет дату следующего старта. Push отправляется, только если дата не `NULL` и приходится на сегодня.
2. **Напоминание о новом цикле:** после закрытия цикла на основе последней тренировки рассчитывается рекомендуемая дата. Начиная с этой даты, приложение присылает не более одного напоминания в сутки с предложением начать новый цикл.

## 11. КОНТЕКСТНЫЙ ФЛАГ «ТРУДОЛЮБИЕ»

* **Условие активации:** устанавливается в момент, когда пользователь полностью выполнил хотя бы одну тренировку (статус «Завершено») в текущие локальные календарные сутки.
* **Время жизни:** действует до наступления новых локальных суток ($00:00$). Сброс цикла на флаг не влияет.
* **Влияние на логику:**
  * Смягчает реакции тренера при последующих частичных результатах или пропусках в этот же день.
  * Делает похвалу более яркой при повторных успехах.
  * Учитывается при формировании реплик возврата к ранее начатым тренировкам («долгам»).
  * **Не применяется** к итоговым репликам цикла.

## 12. МОДЕЛЬ ДИАЛОГОВ И РЕПЛИК ТРЕНЕРА

Все реплики тренера строго детерминированы и распределены по категориям. Динамическая генерация текста отсутствует.

### Маршрутизация реплик при навигации

#### Сценарий А: «Завершил тренировку $\to$ отдельно начал следующую»
1. Тренер озвучивает итог предыдущей тренировки (если он не перекрыт итогом цикла).
2. Озвучивается реакция на старт следующей тренировки.
3. Если активен флаг «Трудолюбие», тренер дополнительно хвалит за продолжение продуктивного дня.
4. Если выбранная тренировка ранее уже открывалась в этом цикле («Отложено» или «Не завершено»), вместо стандартного приветствия используется реплика возвращения к долгу.

#### Сценарий Б: «Прямое переключение»
1. Тренер даёт короткий комментарий непосредственно по факту переключения.
2. Промежуточный итог закрываемой тренировки и приветствие новой тренировки **подавляются**.
3. Стандартная похвала за «Трудолюбие» не воспроизводится.
4. Если переключение привело к установке/переносу флага Hot, тренер произносит специализированную реплику напоминания о Hot-долге.

#### Сценарий В: «Возвращение к ранее начатой тренировке (без прямого переключения)»
1. Если перед этим была закрыта другая тренировка, сначала выводится её итог.
2. Далее выводится реплика о возвращении к оставленному делу (вариант фразы зависит от наличия флага «Трудолюбие»).

## 13. КАТЕГОРИИ РЕПЛИК О ДОЛГАХ

Для проектной документации и наполнения базы реплик зафиксированы три рабочих типа фраз о возвращении к незавершённым тренировкам:

1. **«Долг после успеха»**
   * *Контекст:* отдельный запуск тренировки, которая ранее уже была начата/отложена в текущем цикле. Не прямое переключение. Флаг «Трудолюбие» **активен**.
   * *Смысловой посыл:* похвала за готовность закрыть старый хвост после уже достигнутого сегодня успеха.
2. **«Возвращение к долгу»**
   * *Контекст:* отдельный запуск тренировки, которая ранее была начата/отложена в текущем цикле. Не прямое переключение. Флаг «Трудолюбие» **не активен**.
   * *Смысловой посыл:* акцент на решимости довести начатое дело до конца.
3. **«Напоминание о Hot-долге»**
   * *Контекст:* прямое переключение привело к установке или переносу флага Hot на исходную тренировку.
   * *Смысловой посыл:* предупреждение о том, что оставленная тренировка удерживает цикл от закрытия и ждёт возвращения в течение часа.

## 14. СЛУЧАЙНЫЕ МОТИВАЦИОННЫЕ ФРАЗЫ

* **Лимит:** не более $1$ случайной фразы за одну активную тренировку.
* **Приоритет:** наименьший в системе. Любое системное событие или плановая реплика отменяют/перебивают мотивационную фразу.
* **Таймаут тишины:** фраза может появиться только в том случае, если в течение последних $10$ минут на экране не появлялось никаких других реплик. Если запланированное время пересекается с другой репликой, показ сдвигается на $+10$ минут.
* При завершении сессии запланированная мотивационная фраза аннулируется и не переносится на следующий сеанс.
